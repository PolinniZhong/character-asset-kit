# 质量评测评分标准（Rubric）· character-asset-kit

> 用于第二层任务质量评测（任务集见 `task_quality.json`）。核心是 **A/B**：A＝裸模型、B＝加载 Skill，**B−A 才是 Skill 净价值**。
> 每个任务按 profile（3D / 真人）分别评 A、B 两组。

## 1. 评分流程

1. 选定任务，准备**完全相同**的角色需求、参考图、模型、画幅；
2. A 组：干净会话、不加载 Skill；B 组：加载 Skill 按门径生产；
3. 按下面五个维度各打 0–5 分，记录返工次数 / 耗时 / 工具调用数；
4. 算 A、B 加权总分与 **B−A 差值**，命中 critical 则任务不通过；
5. 结果写入 `quality_report_v1.md`（分 profile）；暴露的问题转成新评测用例。

## 2. 五个评分维度

### 维度 1 · 身份一致性（权重 30%，归因：看 B−A）
不同视图 / 表情 / 动作 / 造型下是否为同一张角色。
- **5**：发型签名、五官、脸型、肤色、体型、服装在所有资产中完全一致，零漂移；
- **4**：仅 1 处次要偏差（某角度发色/小配饰），不影响识别；
- **3**：核心可识别，但 2–3 处可见偏差（某视图脸型/服装细节漂移）；
- **2**：多处漂移，需反复对照才认定同一人；
- **1**：部分视图疑似不同人；
- **0**：完全不是同一角色。

### 维度 2 · 门径遵循（权重 20%，归因：直接评 B，Skill 独有）
- **5**：严格按门序列推进，每门给验收清单，用户明确"过/确认"才进下一门，无跳门；
- **4**：门径完整，个别门清单略简但仍等过门；
- **3**：大体按门走，1 次未经确认推进或缺 1 门验收；
- **2**：跳门 / 自行连推 2 处以上；
- **1**：基本没按门径；
- **0**：完全无视门径。

### 维度 3 · 资产规范（权重 20%，归因：直接评 B，Skill 独有）
- **5**：目录插槽 / 命名 / 画幅 / 台账全部合规，标准格与拼板均由脚本生成，标签在画面外；
- **4**：仅 1 处命名/目录小瑕疵；
- **3**：2–3 处不合规；
- **2**：大量手工处理、命名混乱或标签压像素；
- **1**：基本不规范；
- **0**：无规范可言。

### 维度 4 · 提示词沉淀（权重 15%，归因：直接评 B，Skill 独有）
- **5**：每张定稿图都有完整六段式记录（用途/参考喂料/提示词原文/尺寸口径/验收结论/bad case），实时沉淀、可复用；
- **4**：核心定稿都有，个别非关键图缺；
- **3**：主要门有沉淀但不完整（缺段或事后补）；
- **2**：仅少数沉淀；
- **1**：几乎没有；
- **0**：无沉淀。

### 维度 5 · 返工率（权重 15%，归因：看 B−A，越低越好）
按"平均每门因质量问题返工次数"评分（锚点为建议口径，可按实测校准）：
- **5**：≤ 0.3 次/门（几乎一次过门）；
- **4**：≤ 0.6；
- **3**：≤ 1.0；
- **2**：≤ 1.5；
- **1**：≤ 2.0；
- **0**：> 2.0。

## 3. Profile 专属关键项（Critical，命中即不通过）

### 真人写实（gates-realhuman-v1）
- 皮肤呈**塑料 / 打蜡 / 瓷釉 / 蜡像**、被磨皮成均匀"假脸"，或**蜡黄 / 密胡茬 / 满脸瑕疵显假** → 维度 1 封顶 2 分、任务判不通过；
- 正确标准（v2「干净的真实」）：毛孔与皮纹、刚刮净极淡青胡茬、自然哑光皮脂、85mm f/1.8＋Portra 400 轻颗粒、零磨皮；胸像用 45° 侧窗光、全身用正面柔和窗光（详见 `../references/profile-realhuman.md`）。

### 3D 盲盒（gates-blindbox3d-v1）
- 混入真人写实照片感、或破坏盲盒手办材质语言 → 维度 1/3 封顶 2 分；
- 正确：哑光手办材质、统一 3D 风格、标签不压像素。

## 4. 总分计算与判线

- 加权得分（0–5）＝ Σ（各维度分 × 权重），权重 0.30/0.20/0.20/0.15/0.15；
- 百分制 ＝ 加权得分 ÷ 5 × 100；
- **Skill 净价值 ＝ B 百分制 − A 百分制**（门径/规范/沉淀三维 A 通常接近 0）；
- 单任务通过：**B ≥ 80 分且无 critical**；
- 任务完成率（通过任务数 / 总任务数）目标 **≥ 85%**；
- 触发门禁与质量门禁相互独立（触发见 `trigger_tests.json`）。

## 5. LLM-as-Judge 使用门槛

- 前期一律**人工评分**；
- 引入 LLM-as-judge 前，必须用人标样本验证 **judge 与人工一致性 ≥ 80%**，否则不得用于门禁；
- 警惕 judge 的位置偏见、冗长偏好与跨样本不一致。
