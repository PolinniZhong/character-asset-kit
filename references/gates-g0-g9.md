# 门径手册 G0–G9（核心生产线）

> 本篇是 character-asset-kit 的主作业手册。每门的结构：**输入 → 生成要点 → 确定性工序 → 验收 → 沉淀**。
> 默认 profile 为 `blindbox3d`（皮克斯/盲盒手办感 3D 角色、纯白底、5.5 头身）；换 profile 见 `style-profiles.md`。
> 提示词模板本体在 `prompt-framework.md`；模型"不听提示词"时的改写配方在 `prompt-rewrite-rules.md`；崩图案例在 `bad-cases.md`。

## §0 运行时绑定（开工前确认）

| 能力 | Doubao 运行时（默认） | 其他运行时的等价替换 |
|---|---|---|
| 文生图/图生图 | `image_gen` / `image_edit`，模型固定 `seedream_5.0_pro` | OpenAI 官方/火山方舟/任意 OpenAI 兼容网关用 `scripts/bin/kit_generate.py`（用法见 `runtime-portability.md` §3）；本地 CUDA（ComfyUI 等）按该文 §6 契约自包。**必须支持多图参考输入**，否则 G2 之后无法做 |
| 调用粒度 | 每次 `request_list` 仅 1 个请求 | 同 |
| 抠图 | `subjectmask`（macOS Vision，随包编译） | 任意高质量主体抠图；对结果走 `kit_standard_cell.py --already-cutout` |
| 像素工序 | 本 skill `scripts/`（Python 3.10+＋Pillow） | 同，脚本与模型无关 |
| 字体 | 冬青黑体 Hiragino Sans GB（PingFang.ttc Pillow 无法直接打开） | 任一中性无衬线 CJK 字体，改 `charkit/fonts.py` 回退链 |

**两条通道优先级（210 张实验结论，贯穿所有门）**：参考图通道 ＞ 文字通道。模型对"定性词/数量词/禁止词"服从度高；对"数值（占高 65%）/状态描述（屏幕合上）"服从度低。凡是数值/状态类要求，优先靠**参考图**或**翻译成外形特征**实现，见 `prompt-rewrite-rules.md`。
> 注意：上述服从度数据与配方 A/B/C 均为 **seedream_5.0_pro 实测结论**，换模型前按 `runtime-portability.md` §4 跑最小再验证，不得把具体成功率搬到别的模型上。

**画幅总表**

| 用途 | 像素 | 备注 |
|---|---|---|
| 母版/标准格（全身、五视图、动作、胸像） | 1773×2364（3:4） | 全身角色高占格 0.80、足底基线 y≈2080；胸像走 `--bust` |
| 细节/道具方格 | 2364×2364（取标准格长边；raw 按 2048×2048 生成） | bbox 0.86 双向居中、无阴影；需要 2048 显式 `--cell 2048x2048` |
| 场景竖/横 | 1773×2364 / 2560×1440 | 横版必须重构图，禁止竖裁横（G12） |
| 拼板/商卡 | 脚本按单元累加，严格 3:4 | 标签一律在画面外 |

**命名总规则**：`{CODE}_{单元类型}-{编号}{名}_v{版本}_{后缀}.png`；后缀 `_白`（白底接触阴影）/`_透明` / 无后缀（胸像用 `_白`）。raw 与候选一律进 `99_过程稿/`，命名 `raw_{单元}_v{n}候选.jpg`。

## §G0 立项与规格卡

**输入**：用户的角色想法（性别/年龄/职业/性格/头身比/发型脸型/服装/风格）+ 可选参考图（只抽感觉，不复制具体 IP）。

**做**：
1. `python3 scripts/bin/kit_init_character.py --dir <CODE>-<slug> --root <库根>` 建包（自动生成规格卡、资产清单、提示词库骨架、subjectmask）。
2. 与用户逐项确认规格卡八字段：**身份 / 头身比与材质 / 头脸（发型签名写到可复现的粒度）/ 服装（含鞋、配饰有无）/ 配色 HEX / 性格与默认表情 / 禁止项 / 风格基调**。信息不齐先问，不自行补关键身份。
3. 代号规范：`<前缀>-<两位序号>-<slug>`（如 `CHAR-01-demo`）；内部代号/真名**绝不入图**。
4. 服装签名印花（若有）在规格卡显式登记为"唯一允许入图文字"，写清内容、颜色、位置。

**验收**：规格卡八字段无空、用户确认；目录树与资产清单已生成；`--all --check` 只有 W2（计划产物未生成，正常）。

**沉淀**：规格卡即权威文件，不另写提示词。

## §G1 白底母版（一致性锚点，最重要的一张）

**输入**：规格卡；可选 1–3 张风格/气质参考图。

**生成要点**（提示词全文用 `prompt-framework.md §母版`，这里只列纪律）：
- 竖 3:4、纯白摄影棚底、单角色居中、完整全身、自然 A 字站姿（双脚与肩同宽、双臂自然下垂微张、手心朝内）、身体与头正对镜头、默认亲和微笑。
- 头身比/材质/发型签名/服装逐字按规格卡；明确禁止项（无眼镜/帽/配饰、非 Q 版、非真人、非 2D 扁平）。
- 零文字硬约束句每次必带（除已登记的签名印花）。
- **占高约 65% 这类数值模型不听**：靠"完整全身、四周留安全边距、头顶脚底不贴边"等定性词，最终占高由标准格归一（角色高 0.80），不要求 raw 一次到位。
- 一次只出 1 张；用户要对比时，候选之间必须有可命名的差异变量。

**确定性工序**：raw 存 `99_过程稿/` → `kit_standard_cell.py` 抠图落格，产出 `01_母版/{CODE}_母版_白底_v1.0.png`（接触阴影 fill(30,42,75,22)、模糊 14）与 `_透明.png`。
- 抠图连发空文件是已知平台问题：前台每批 ≤3 张、间隔 3 秒重试；输入已是透明 PNG 时用 `--already-cutout`。

**验收（用户过门）**：身份签名逐项对规格卡；白底无灰雾（有灰雾重抠重落底，不直接用）；无任何文字/角标/第二人物；完整不裁切；本地 PNG 放大核对（不以聊天缩略图为准）。

**沉淀**：`08_提示词库/{CODE}_母版提示词_v1.0.md` 六段式；raw URL 记录。

## §G2 五视图多视图

**单元**：正面 / 前四分之三 / 正侧 / 后四分之三 / 背面，各 1 张全身标准格；正面可直接由母版复制（同一 A 站姿）。

**生成要点**：
- 每单元**独立生成**，参考图固定喂「白底母版（最高权重）＋已过门的相邻视角」；**绝不回指上一张同类型失败图之外的链**（永远回指母版，避免误差累积）。
- 提示词用 `prompt-framework.md §五视图`，每格写死该视角的外形要点（侧面只露一只耳朵、背面看不到五官、发型背面/裤后袋/鞋后跟等），并逐格带"服装/发型/体型与参考完全一致"。
- **发型签名必须拆成可核对的细项枚举**（BC-34）：不能只写"与参考图发型一致"，要写死"高发髻＋左右对称发簪＋右侧步摇＋后颈长发垂落"等每一个细节；特别是背面/侧面能看到的后颈区域（碎发/长发/干净），最容易被模型"自由发挥"。
- **镜像防崩**：正侧与四分之三必须显式写"面朝画面右侧/左侧"并指定可见侧；模型对左右服从差，验收时逐格查朝向，错了单格重跑，不整板重来。
- 背面/后四分之三若有签名印花/帽子等背面特征，显式描述。
- **文件命名必须与资产清单一致**（BC-35）：init 模板统一为正面/前四分之三/正侧/后四分之三/背面，禁止手工创建别名文件（如"前3-4"）；重做前先 grep 资产清单确认实际引用的文件名。

**确定性工序**：逐张 standard_cell（`02_多视图/单图/`）→ `kit_build_board.py --type multiview` 出干净版，加 `--review` 出验收版（对齐线/格框，用于自查不交付用户当成品）。

**验收**：五格同一套服装/发型/体型/鞋；**发型逐格与母版核对**（发髻形状、发簪位置、后颈碎发/长发、刘海）；脸仅正面与前 3/4 可见且与母版一致；朝向正确无镜像；足底基线齐；角色高一致；板上标签在画面外。

**沉淀**：`{CODE}_多视图设定图板提示词_v1.0.md`。

## §G3 细节特写

**单元**：6 个签名细节方格（raw 2048×2048，落格 2364×2364），默认槽位：1 发丝 / 2 眼部 / 3 领口 / 4 裤脚（或下摆/腰头）/ 5 鞋 / 6 手部；有配饰/帽的角色换成签名配饰（如反戴帽、帽檐、印花）。槽位语义写进规格卡附录与 G14 config。

**生成要点**：
- 同样用配方 A 取景句式："极端特写，只拍{部位}，画面中没有其他部位"，逐部位列禁止项。
- **发丝格必须参考 G2 多视图（正面＋背面），不能只参考母版**：母版是全身图，发髻/发簪细节占比小，模型在微距时会"自由发挥"。丰富发型（古风发髻、复杂发饰、帽饰）尤其要喂背面视图——正面看不到的发簪布局、步摇垂坠方向只有背面能钉死。简单发型（短发、马尾、3D 盲盒）可只参考母版。
- 发丝要成簇有体积、有签名翘发；眼部不放大到萌系超大眼；印花/配饰细节必须与规格卡登记一致。
- 道具与细节分开：道具归 G7，不占 G3 槽位。

**确定性工序**：standard_cell `--square`（2364、bbox 0.86、无阴影）→ build_board `--type detail`。
- **抠图失败兜底（两条确定性路径）**：①面部微距格让皮肤/材质满幅到四边、五官不悬空、不要白底，raw 直接 `--already-cutout` 落格（Vision 会把面部微距的皮肤当背景剥掉）；②深色道具 Vision 确定性 `no subject found` 时，用 `kit_colorkey_cutout.py` 对纯白底做边缘泛洪色键，再 `--already-cutout`。standard_cell 现在会把 Vision 失败原因直接打到 stderr（exit 2），不再抛下游 UnidentifiedImageError。

**验收**：六格细节都能在母版/视图上找到对应；**发丝格的发簪/发饰布局与 G2 正面＋背面一致**（丰富发型必查）；无文字压图；手部特写五指正常（手部是高频崩点，崩了单格重跑）。

**沉淀**：`{CODE}_细节特写提示词_v1.0.md`。

## §G4 基础表情（头肩通道）

**单元**：0 中性 / 1 微笑 / 2 思考 / 3 露齿笑 / 4 惊讶 / 5 严肃，共 6 张**头肩胸像**。

**生成要点**：
- **参考图喂「G2 正面视图＋G3 发丝格」**（丰富发型）或「母版＋G3 发丝格」（简单发型）；不要只用母版——母版全身图的发髻细节不足以锚定头肩特写的发型。G2 正面视图提供正面发型锚（发髻高度、两侧发簪位置），G3 发丝格提供背面/细节锚（发簪布局、步摇方向）。
- 胸像通道 `--bust`（高 0.925、顶部 3.5% 边距、无阴影）。
- **取景必须正向写死**（配方 A，实测改后 10/10）："头肩胸像特写，画面下沿自然切在上胸，只拍头、颈、肩与上胸"，并**逐列禁止**"不要腰、不要骨盆、不要大腿、不要小腿、不要脚、不要全身"。只写"特写"模型会给半身甚至全身。
- 表情靠 AU 叠加，不靠拧五官：
  - 思考＝视线偏移＋下颌微收＋轻微歪头；**禁止皱眉/倒八字眉**（防过冲成生气）。
  - 严肃＝正视镜头＋下颌微收＋嘴角自然；**禁止怒眉/眯眼/嘴角下撇**。
  - 惊讶＝抬眉＋睁眼＋嘴微张，幅度分档；微笑默认闭唇，露齿笑才开口。
- 表情板只出现**头与肩**，不带手（手在 G6）。

**确定性工序**：standard_cell `--bust` → build_board `--type expression`（＋`--review`）。

**验收**：六格同一张脸（发型签名/脸型/肤色一致）；**六格发型完全一致**（发髻高度、发簪位置、步摇方向逐格比对，丰富发型必查——同一组里出现两种发型即不通过）；表情可读且不过冲；无全身混入；板内无文字压脸。

**沉淀**：`{CODE}_表情提示词_v1.0.md`。微表情矩阵（情绪族×强度）是 G10，不在本门。

## §G5 营销胸像

**单元**：前 3/4 头肩胸像 1 张（用户可指定加正脸/侧脸），用于头像、封面、名片位。

**生成要点**：默认亲和微笑、视线看镜头、白底；可允许轻微身体斜侧但签名发型/服装清晰；仍是 `--bust` 通道、无接触阴影。

**验收**：脸与 G4 微笑一致；构图适合圆形/方形裁切（头顶与两侧留余量）。

**沉淀**：并入母版或表情提示词文档，注明营销用途与裁切口径。

## §G6 动作姿态

**单元（blindbox3d 默认表，可按角色裁剪）**：
- A 手势组：A1 挥手 / A2 抬手讲解 / A3 摊开双手 / A4 抱胸 / A5 托腮；
- B 身势组：B1 行走 / B2 奔跑 / B3 端坐；
- C 职业动作（依赖 G7 道具，排在 G7 之后做）：C1 敲键盘 / C2 持平板 / C3 指屏幕 / 看手机。

**生成要点**：
- 每张全身标准格，参考图永远回指母版＋相关视图；动作描述具体到四肢与重心（"右手抬起至肩高、掌心向外，左手自然下垂"）。
- **坐姿几何（配方 C）**：纯文本写"端坐"几乎必崩（宽蹲/盘腿），实测 0/5；**挂一张坐姿参考图**可达 5/5。落格用 `--scale-factor 0.58` 左右（坐姿身高变矮，不能按站姿 0.80）。
- C 组手持设备：设备必须**握在手里/托在手里**（笔记本是握住主机部分、不是悬空在肩旁），写死左右手分工与"全图严格只有两只手、每只手五根手指、手指清晰不融合，禁止第三只手/多余手臂"。
- 道具比例走盲盒夸张口径（见 G7），本门不重新设计道具。

**确定性工序**：standard_cell（坐姿 `--scale-factor 0.58`）→ build_board `--type pose`。

**验收**：动作可读、重心合理；手指数目正确；服装/发型不漂；坐姿不宽蹲；道具手持关系自然。

**沉淀**：`{CODE}_动作姿态提示词_v1.0.md`。

## §G7 单体道具与手持关系（三步，顺序不能省）

1. **单体独立图**：道具单独居中、2364×2364 方格（`--square --no-shadow`，bbox 0.86 双向居中，完整不裁顶）、白底；**不要用** `--fig-ratio 0.72 --sole-ratio 0.5` 组合（高主体必然裁顶，脚本现已对越界直接报错）；深色道具 Vision 失败走 `kit_colorkey_cutout.py` 色键兜底；材质必须符合世界观（blindbox3d 下为哑光塑料/磨砂科技材质＋克制的电光蓝边缘微光）。道具造型在规格卡或道具提示词文档登记。
2. **比例对照图**：角色以标准站姿与道具同框，**用脸宽/头高做锚点**写尺寸（"平板宽约 1.2 个头宽"），不要用肩宽倍数（实测锚点不稳）。盲盒手办口径允许道具夸张，用户接受"比真实略大"，但不能手机比头大、电脑小到看不清。
3. **手持关系图**：道具**被手握住/托住**，接触点清晰；这是 C 组动作与场景包的唯一道具参考。

**手持设备防崩原句（含设备的图必带，G12 同源）**：
- 屏幕："极暗近黑、只有极微弱冷色反光，不发光、不向背景投射光幕/光束/光爆"；
- 背景光："只是圆形柔和光晕，绝不能出现矩形或方形亮块"，禁止"第二块屏幕/第二台设备/矩形发光面板"；
- 手部："全图严格只有两只手、每只手恰好五根手指"，写死左右手分工。

**确定性工序**：单体/对照走 `--square --no-shadow`；手持关系可走标准格；build_board `--type prop`。配饰（眼镜等非手持物）放 `07_道具/配饰变体/`，**不进 G14 训练集**。

**验收（曾两次被否，按此口径）**：设备是被握住的、不悬空；比例通过对照图确认；屏幕暗、背景无矩形光幕；放大查手指与设备数量。

**沉淀**：`{CODE}_单体道具提示词_v1.0.md`，记录被接受的比例锚点数值与 bad case。

## §G8 拼板、角色设定板与商卡

- 技术板（multiview/expression/detail/pose/micro_expression/gaze/character_sheet）一律脚本构建：**干净版**交付，**验收版**（对齐线/格框）只用于自查。
- **角色设定板（character_sheet）**信息架构：上部左 40% 前 3/4 胸像 ｜ 右 60% 2×2 全身网格；其下信息栏（身份/头身/材质/发型/服装/鞋/配饰/禁止项 8 字段）＋配色 HEX；再下表情一排 5 格；底部细节 3 列 2 行。2430×3240 严格 3:4，文字自动收进列宽，**禁止压字**。
- **清单配置**：`boards.character_sheet` 段（version/meta/height=3240/out_clean/out_review/fields 八行）模板已内置；8 字段值必须逐字取自规格卡。**`meta` 是会画到成品板上的对外文字，不是备注栏**——禁止把缺口编号、内部说明写进任何板的 meta。`--type all` 缺核心板配置段会打 WARN；单独构建缺段会明确报错（不再 KeyError/静默跳过）。
- **商卡（card）**按资产清单的 card 配置构建；标签、字段名全部在排版层（图框之外），**绝不压在角色像素上**。
- 字体用中性无衬线（冬青黑体/苹方系）；细字重下有衬线或系统默认中文字会发毛，禁止使用。
- 板内出现的任何文字只能来自资产清单/规格卡，不现场编造身份描述。

**验收**：打开成品 PNG 放大逐块核对；文字无压图、无溢出、无错别字；HEX 与规格卡一致；干净版无对齐线。
