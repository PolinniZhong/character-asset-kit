# 崩图 / 事故目录（bad cases）

> 每条四段：**现象 → 根因 → 修法 → 首现门**。新失败重复两次必须回灌本文件并顺延编号。
> 判级口径：**整张能用 / 小崩可修（单格重跑可救）/ 不可用（身份或结构性失败）**；单格失败只重跑该格。
> BC-01–27 整理自早期生产与 210 张受控复现实验；BC-28–33 来自第三个角色 dogfooding 与入库阶段。

## 一、底图与身份（G1–G2）

- **BC-01｜"白底"直出带灰雾与投影**：模型把"白底"理解成棚拍环境，给灰渐变和环境投影。→ 提示词显式写纯白 #FFFFFF 无缝底，且不接受灰雾底，raw 落格时强制抠图重落纯白。G1。
- **BC-02｜文字调比例导致头身漂移**：文字写"六头身"会把盲盒角色拉向真人比例，丢掉手办感。→ 头身比锁进 profile（如 5.5），提示词禁止"写实真人比例"，数值不交给现场发挥。G1。
- **BC-03｜母版背景用深色氛围渐变**：氛围底好看但干扰后续抠图与商卡复用。→ **标准母版统一纯白无缝底**；氛围/场景图是 G12 的事，母版不兼做氛围图。G1。
- **BC-04｜同衣不同光导致配色漂移**：HEX 只写在文字里，各单元光照不同就变色。→ 拼板带 HEX 色板条，关键色升为锁定值，落格后对照色板抽检。G2/G8。
- **BC-05｜背面视角直出成"正面＋背面两个人并排"**：把多格身份板整板当参考，模型复制其多格版式。→ 单单元生成**禁止喂多人整板参考**；需要背面就从身份板裁出单人背面格再喂；提示词顶部固定"有且只有一个人物，禁止并排/多格/第二张脸"。G2。
- **BC-06｜侧面朝向反（镜像）**：左右侧不分，纯文本纠正服从度低。→ 显式写"面朝画面右侧/左侧"并点名可见侧（左耳/左侧轮廓）；逐格目检，镜像单格重跑。G2。
- **BC-07｜数值占高指令不被执行**：文字写"角色占画面 65%"基本无效，模型跟参考图的占高走（实验：参考 65.8% 成片就 65–74%，参考 79% 成片 76–87%）。→ 占高/景别交给参考图与标准格归一，提示词只留定性方向。G1/G2。
- **BC-08｜参考图缺陷被逐参数继承**：带缺陷废稿当参考，构图、肤色暖度、轮廓光、印花全部被继承（两组对照实验证实，方向一致、幅度温和到明显不等）。→ 喂参考前先评估其构图/光色，缺陷明显先修参考图；"不复制参考构图"这句基本无效，要用正向外形描述覆盖。跨门。

## 二、五官、表情与取景（G3–G5、G10）

- **BC-09｜表情 raw 按全身生成，拼板后身腿入镜、脸占比不足**：表情板要求头肩但没在提示词里写死取景。→ raw 阶段固定头肩胸像取景（配方 A），落格走 `--bust`；整批身腿入镜作废重出。G4。
- **BC-10｜要胸像/特写却给全身**：取景边界靠模型默认。→ 配方 A：正向写死"画面下沿自然切在上胸，只拍头颈肩与上胸"＋逐列禁止"腰/骨盆/大腿/小腿/脚/全身"，并用参考图锚定景别（纯文本下特写失败率显著更高）。G3/G4。
- **BC-11｜负面情绪过冲成表情包**：思考/严肃被画成皱眉怒目。→ 固定防过冲句：思考＝视线偏移＋下颌微收＋轻歪头，附"不皱眉/不倒八字眉/不生气/嘴角不下撇"；严肃＝正视＋下颌微收＋嘴角持平，附"不怒眉/不眯眼/不咬牙"；强度靠 AU 叠加不靠拧五官。G4/G10。
- **BC-12｜面部微距被抠图工具剥皮**：系统语义分割把满幅皮肤当背景剥掉。→ 微距 raw 让皮肤铺满画面，外部抠图后用 `--already-cutout` 落格，不走语义分割。G3。
- **BC-13｜肤色在版本间偏暖/偏粉**：肤色跟随参考图暖度，文字"白一点"没有可复现刻度（出现过"再白 15%"被做成惨白）。→ 肤色以 HEX 区间锁定，调色只做小幅步进并以**上一版**为基准描述，不使用绝对化形容词。G1/G3。

### 追加（2026-09-22 真机实测）

- **BC-34｜两张参考图景别冲突，模型把主体撑满整幅（新维度：参考图配置）**：
  追加密一个表情格时，喂"全身母版（占高 65.4%）＋胸像构图锚（占高 90.9%）"这种"看似稳妥"的双锚组合，
  模型**两张都不跟**，把主体放大到 **100% 占高、头顶贴边**；换成**单锚＝胸像**（占高 90.9%）后，输出 **95.3%**、落格后 **90.4%**，与基准格一致。
  同一轮里，把**成品表情格**（头已放大）当构图锚同样失败（照抄其放大构图）；
  把取景写成**明文百分比**（"头顶留白约 4.5%""下巴在 55%""宽度不超 70%"）也仍被 100% 忽略。
  → **构图锚一次只给一个、且必须与目标同景别；不要拿成品资产当锚；不要混景别喂双锚**。
  排查顺序：**参考图配置 → 模型 → 提示词**（六轮失败中前五轮全是参考图问题，与模型能力无关：Pro/Lite 在锚配对时都听话）。
  详见 `prompt-rewrite-rules.md` §7。G3/G4/G5（凡"以参考图生成"的门都适用）。

## 三、四肢、动作与道具（G6–G7）

- **BC-14｜多一只手 / 手指融合**：手持道具、指屏幕等交互动作高发。→ 数量词写死（两只手、左右手各做什么、五根手指），放大目检手部；崩了只重跑该格。G6/G12。
- **BC-15｜复杂姿态纯文本必崩**：端坐/蹲坐纯文本 0/5（全给宽蹲/盘腿），挂几何参考图 5/5。→ 配方 C：复杂人体几何固定"先出/找一张几何正确参考 → 构图参考＋母版身份参考"二步生成；落格按姿态给 `--scale-factor`（端坐约 0.58）。G6。
- **BC-16｜道具比例失调（手机太大、电脑太小）**：模型对手持物体无稳定尺度，文字数值比例服从度低。→ 以**脸宽/掌宽**为锚做比例对照板，手持关系图过用户目检；盲盒风格允许适度夸张，夸张幅度由人确认后锁定。G7。
- **BC-17｜道具悬空在肩侧、手与物体无接触**：模型回避画握持关系。→ 明确写"整只手掌握住/抱住物体，手指与物体接触、物体贴在掌心/胸前"，禁止悬浮；手持关系不过单格重跑。G7。
- **BC-18｜单体道具姿态废稿（V 形叉开、倾斜）**：单体图模型仍会"摆造型"。→ 单体要正投影、中立摆放、完整不裁；走 `--square --no-shadow`，不与手持图混用。G7。
- **BC-19｜设备/背景被染成发光屏幕**：场景里出现第二块亮矩形，或背景墙变成屏幕光幕（曾出现三只手级别的结构性崩图）。→ 配方 B：把"屏幕合上/锁屏/黑屏"翻译成外形（闭合深色盖板/近黑玻璃矩形，无屏幕面无发光面无界面元素）；背景固定"只有圆形柔光，禁止矩形亮块、禁止第二设备"。G7/G12。

## 四、拼板、文字与工程纪律（G8、跨门）

- **BC-20｜整板直出多视图变脸、视角重复**：单 prompt 多视角一致性仅约 65–75%。→ 路线反转：**逐单元生成、回指母版、脚本拼板**，从工艺上消灭整板直出。G2/G8。
- **BC-21｜标签/说明文字压在角色脸上或资产像素上**：拼板标签内联绘制污染像素，还干扰后续模型识别。→ 铁律：标签一律在画面外（框下/栏外留白区），任何板型不得压像素。G8。
- **BC-22｜拼板细字体发毛、像有线体衬线**：过细的中文黑体在小字号下发虚。→ 统一用无衬线 CJK 字体（macOS 默认冬青黑体；其他平台显式指定可用无衬线 CJK），标签最小字号写进板型。G8。
- **BC-23｜抠图偶发空文件**：语义抠图偶发返回空结果却继续落格。→ 落格前检查产物存在与非空，失败按重试纪律（≤3 次、间隔），仍失败转色键/外部抠图。G4/G7。
- **BC-24｜服装印花/文字在零文字禁止句下漏网**：参考图本身带印花时，纯禁止句偶发失效（实验 60 张漏 1）。→ 零文字禁止句逐图固定且枚举要全（文字/字母/数字/符号/logo/水印）；漏网单格判小崩可修、重跑；母版是否允许固定印花由规格卡显式声明。跨门。
- **BC-25｜横版画幅被模型等比替换**：请求 2560×1440 实际返回 2730×1536（仍精确 16:9）。→ 比例正确即接受，拼板按固定格 contain 吸收；台账记录实际像素，不按请求像素登记。G12。
- **BC-26｜混用模型版本**：中途用非预注册主力模型出探针图，口径不可比。→ 只用 profile 预注册模型；误用批次整批作废、隔离目录、不进统计与资产。跨门。
- **BC-27｜"整张能用"误判**：文字/状态类硬伤曾被一刀切判不可用，与单格可修的事实冲突。→ 口径收窄：单格重跑可修的文字/状态问题归**小崩可修**；只有身份漂移、整格结构性崩坏才判不可用。跨门。

## 五、工具链与入库（dogfooding 与资产中心阶段）

- **BC-28｜系统抠图对深色小道具确定性失败、对面部微距过度分割**：macOS Vision 对深色道具报 `no subject found`（重试无效），对满幅皮肤语义剥皮。→ 三路径：macOS Vision（默认）／`kit_colorkey_cutout.py` 纯白底色键（深色道具兜底）／外部抠图＋`--already-cutout`（微距与非 macOS）；报错必须带 returncode 与兜底指引。G4/G7。
- **BC-29｜道具方格错误参数组合必然裁顶**：`--fig-ratio 0.72 --sole-ratio 0.5` 几何上顶部越界 0.22H。→ 单体统一 `--square --no-shadow`；落格函数对 y<0 直接 ValueError，不静默裁切。G7。
- **BC-30｜CLI 假绿灯**：`--all --char .` 解析为空集却 exit 0 无输出，曾漏登记 28–29 个 PNG。→ `--all` 与 `--char` 互斥报错；枚举为空、库根不存在一律 exit 2 并给改正指引。跨门。
- **BC-31｜清单 meta 内部备注被画到成品上**：板配置的 `meta` 字段是成品文字，不是备注栏。→ 模板 `_comment` 明示；内部备注一律不进清单 meta。G8。
- **BC-32｜微表情板为空情绪族渲染空白行**：可选族 levels 为空仍占行（板高虚高、只有竖排族名）。→ 构建器自动跳过 levels 为空的族，板高按实际族数计算。G10。
- **BC-33｜复用母版当正面用字节拷贝，导致上层资产中心串号**：正面文件与母版字节完全相同，按内容指纹去重的资产系统把两者判成同一身份。→ 正面即使视觉复用母版，也要经标准格**重新落格**产出独立文件（重编码即不同指纹）；已入库才发现则给正面行分配独立身份 ID（身份按路径稳定）。G2/入库。

### 追加（2026-09-26 古风真人 KR-03 dogfooding）

- **BC-34｜多视图发型漂移：半披发被做成全盘髻后颈干净（新维度：发型签名权威源）**：
  母版是"高发髻盘起在头顶 **＋ 脖子后面/肩后有长发自然垂落到背部**"（半披发），但 G2 多视图生成时模型"自由发挥"，把背面/侧面做成了**全盘髻、后颈干净**。因为 G2 是后续所有门的发型锚点，G3 发丝格和 G4 表情全部继承了错误的后颈干净版本，与母版不一致。
  根因：①prompt 只写了"高发髻"，没写死"脖子后面有长发垂落"这个容易被忽略的特征；②生成后没有逐格与母版核对发型（只查了服装和脸）。
  → **母版是发型的唯一权威**，多视图生成时必须**逐格与母版核对发型签名的每一个细节**（发髻形状、发簪位置、后颈是否有碎发/长发、刘海形状）；prompt 必须把发型签名拆成可核对的细项枚举（"高发髻＋左右对称发簪＋右侧步摇＋后颈长发垂落"），不能只写"与参考图发型一致"。
  排查顺序：**先对母版核对发型 → 再查服装 → 再查脸**。G2（凡多视图生成都适用）。

- **BC-35｜多视图文件命名不一致，重做被忽略（新维度：资产清单契约）**：
  目录下同时存在"前四分之三"和"前3-4"两套命名（init 模板与手工命名混用）。重做背面视图时覆盖了"后3-4"文件，但资产清单引用的是"后四分之三"，导致用户看到的拼板还是旧版（后颈干净），误以为重做没生效。
  → **多视图文件命名必须与资产清单完全一致**；init 模板统一命名（正面/前四分之三/正侧/后四分之三/背面），禁止手工创建别名文件；重做前先 `grep` 资产清单确认实际引用的文件名。G2/入库。

- **BC-36｜丰富发型单张母版参考不足以钉死发簪布局（新维度：多视图→细节→表情三级锚定）**：
  古风发髻＋复杂发饰（左右对称花枝发簪＋珍珠步摇），G3 发丝格只参考母版全身图时，发簪占比太小，模型只体现了右侧一个发簪（左侧缺失）；G4 表情用这个不准的发丝格做锚，导致同一组 6 张出现两种发型（4 张单侧发簪、2 张发髻形状漂移）。
  → **丰富发型必须三级锚定**：①G2 多视图（正面＋背面，钉死完整发型签名）→ ②G3 发丝格（参考 G2 正面＋背面，微距钉死发簪布局和后颈长发）→ ③G4 表情（参考 G2 正面＋G3 发丝格双锚，写死发型细项）。简单发型（短发/马尾/3D 盲盒）可降级为母版单锚。
  验收新增：G3 发丝格发簪布局与 G2 正面＋背面一致；G4 六格发型完全一致（发髻高度、发簪位置、步摇方向、后颈长发逐格比对），同一组出现两种发型即不通过。G3/G4。

- **BC-37｜prop 板型误用 items 数组导致 IndexError**：
  首次配置道具板时用了 `items` 数组（与 multiview/expression 等板型相同），导致 `IndexError: list index out of range`。
  根因：prop 板型用 `solo`（单体）+ `held`（手持）两个独立数组，且不含比例对照图；与其他板型的 `items` 结构不同。
  → 配置 prop 板时必须用 `solo` 和 `held`，比例对照图保留在目录但不进拼板；init 模板的 prop 段已标注此差异。G7。

- **BC-38｜gaze 板 front_ref 路径过期（G3/G4 门序对调的连锁遗漏）**：
  G3/G4 门序对调后，表情文件从 `03_表情/` 移到 `04_表情/`，且文件名去掉了"0"前缀（`表情-0中性` → `表情-中性`）。但资产清单中 gaze 板的 `front_ref` 仍指向旧路径，导致 `build_gaze` 报 `FileNotFoundError`。
  根因：门序对调时全局替换了目录引用，但 gaze 板的 front_ref 是独立字段，不在批量替换范围内。
  → 门序对调/目录重命名后，必须 grep 资产清单中所有路径字段（包括 front_ref、neutral_ref 等引用字段），不能只替换目录名。G11/跨门。

- **BC-39｜G14 训练素材空目录残留（封存前未检查空插槽）**：
  G0–G12 全部完成后，`11_训练素材/` 目录为空（只有 scaffold 创建的空目录），缺少 `trainset.config.json`、`训练外执行指南.md` 和 `datasets/`。
  根因：做 G0–G12 时完全忽略了 G14，认为"不做 LoRA 训练"就等于"不做 G14"。但 G14 是"训练素材备料"（从已有白底资产抽取数据集），不是"训练"本身——WL-01/WL-02/KR-01/KR-02 都做了 G14 备料但不做训练。
  → **G9 封存前必须检查所有插槽目录是否为空**：空目录要么补内容（G14 必须创建 config 并跑 `kit_trainset.py --build`），要么显式标注"本角色不做此门"并删除空目录。"不做训练"≠"不做 G14 备料"。G14/封存。

- **BC-40｜G12 场景包只做单图，缺场景母版和拼板（交付清单不完整）**：
  做 G12 时只生成了单图（竖版+横版），`场景母版/` 和 `拼板/` 目录为空。
  根因：G12 的目录结构要求 `{场景母版, 单图, 拼板}` 三个子目录，但执行时只关注了"生成场景图"这一个动作，忽略了场景母版（场景概念图/设计锚点）和场景包总览拼板。
  → G12 完成清单必须包含三项：①场景母版（场景概念图，放在 `场景母版/`）；②单图（每场景竖版+横版，放在 `单图/`）；③拼板（所有场景图的总览板，放在 `拼板/`）。缺一不可。G12。

- **BC-41｜资产档案 ID 规则搞反导致 E8 串号和分组键冲突**：
  首次手动添加资产档案时，把白/透明版本（media）用了**不同** asset_id，把干净版/验收版（deliverables）用了**相同** asset_id。导致 `--assign-ids` 分组键冲突（白/透明同组不同 ID）和 E8 跨身份串号（干净版/验收版同 ID 被判定为串号）。
  正确规则：**白/透明（media）共用 asset_id、content_id 不同**（同一资产的不同 finish）；**干净版/验收版（deliverables）用不同 asset_id**（不同的交付物）。
  → 手动添加资产档案前，先读 KR-01 等已封存角色的档案作为模板；`--assign-ids` 报分组键冲突时，先检查是否把白/透明用了不同 ID。入库/封存。

- **BC-42｜build_prop 的 --review 总是输出干净版（验收版需手动复制）**：
  `kit_build_board.py --type prop --review` 应该输出验收版（带对齐线/格框），但实际总是输出干净版路径。
  根因：`build_prop` 函数末尾硬编码了 `cfg["out_clean"]`，没有根据 `guides` 参数切换到 `out_review`。
  → 临时修法：干净版生成后手动复制为验收版（验收版只是自查用，与干净版视觉相同不影响交付）；根因修复待改 `build_prop` 的输出路径逻辑。G7/工具链。
