# PRD · 千面工坊·角色资产生产线（character-asset-kit）

## 1. 背景与问题

图像生成模型让"生成一个好看的角色"变得很容易，但"拥有一个角色"是另一回事。生产中反复出现的痛点：

- 同一个角色在不同角度、表情、动作、场景下**长相漂移**，无法作为稳定 IP 使用；
- 整板提示词（一次让模型出"三视图＋表情＋色板"）**必然局部崩**，崩了只能整板重来；
- 图散落在聊天记录里，没有规格、没有台账、没有验收口径，换人/换项目即失传；
- 提示词是"玄学"，成功不可复现，失败不沉淀；
- 想做 LoRA 训练时才发现数据集规格混乱（景别不一、caption 缺失、val 未分层）。

本项目把一条**真实跑通并经过对照实验检验**的角色生产线封装成 Agent Skill：Agent 负责审美判断与模型调用，Skill 提供门径 SOP、提示词方法论与确定性脚本。

## 2. 目标用户

1. **内容/IP 团队**：需要固定角色反复出现在公众号、小红书、短视频封面中。
2. **AI 插画/设计工作流作者**：希望把"怎么做一个角色库"的流程固化给 Agent 执行。
3. **训练数据准备者**：需要规格统一、带双 caption profile、分层 val 的 LoRA 数据集（G14）。

## 3. 目标与非目标

### 目标

- 一个新角色从立项到封存（G0–G9）全程有门径、有验收、有台账；
- 所有**像素排版与对账确定性化**（脚本完成），所有**审美判断留在人＋Agent**；
- 画风、门集合、插槽、画幅全部 **profile 化**：默认盲盒 3D 只是一个 example，不绑定任何具体角色或画风；
- 提示词六段式沉淀，失败案例（bad cases）可回灌、可迭代；
- 单角色生产结束后产出：母版、五视图、表情、细节、胸像、动作、道具、商卡/角色设定板、（扩展）微表情矩阵、机位视线、场景包、风格变体、训练备料。

### 非目标（明确不做）

- **不做 LoRA 训练本身**：G14 只产出数据集与训练外执行指南，训练在库外用 kohya/ai-toolkit 等完成；
- **不做图像生成模型**：生图能力由运行时（豆包/Claude/ComfyUI 等）提供，Skill 只规定喂料与验收；
- **不做文章配图型插画**（那是风格型插画 skill 的场景）；
- **不做真人写实照片、不模仿在世艺术家**；
- **不提供 GUI/桌面应用/在线服务**：形态是 Agent Skill＋脚本目录。

## 4. 形态决策：为什么是 Skill 而不是 CLI / Agent / 模板包

| 候选形态 | 判断 |
|---|---|
| 独立 CLI（如审计类工具） | 否。生图生产天然发生在 Agent 运行时，价值在"编排 Agent 怎么生"（门径、喂料、参考链、验收），CLI 无法承担 |
| 自主 Agent | 否。过门决策与人审不可省略，Agent 应是执行者；Skill 作为知识与工具被任意 Agent 加载即可 |
| 纯提示词模板包 | 否。拼板/落格/台账是确定性工序，没有脚本就回到"整板直出必崩" |
| **Agent Skill（references 大脑＋SKILL.md 路由＋确定性脚本）** | **采用**。与运行时解耦，模型可替换，脚本零必需重依赖 |

## 5. 核心使用流程（用户视角）

1. 用户："建一个新角色"→ Agent 读 SKILL.md，跑 init 生成角色包骨架；
2. 一起完成规格卡（身份签名、HEX、裁剪声明）→ G0；
3. 逐门生产：母版 → 五视图 → 表情 → 细节 → 胸像 → 动作 → 道具 → 拼板/商卡 → 封存；
4. 每门：Agent 门内自检＋单格返工 → 干净版＋验收版一次交用户过门；
5. 需要时启用扩展门（微表情矩阵、机位视线、场景包、风格变体、训练备料）；
6. 封存：台账 0 ERROR、提示词库齐、版本留档。

## 6. 验收标准（产品级）

- 全新对话、只给 Skill，能独立走完 G0–G9（已由第三个角色的 dogfooding 验证，见 `docs/DOGFOODING.md`）；
- 任何一门的拼板都由脚本确定性产出（定尺、标签画面外、不压字）；
- 台账对账可重复、0 ERROR 才能封存；
- 公开仓零私有信息：不含任何私有角色名、内部路径、未授权素材。

## 7. 发布形态

MIT；中文文档为主，README 提供英文版；`scripts/` 可直接用系统 Python 3.10+ 与 Pillow 运行；macOS 抠图为可选增强（Swift 源码随仓、现编译），非 macOS 有文档化替代路径。
