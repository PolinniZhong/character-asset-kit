# 自用验证报告（Dogfooding Report）· v1.1

> 方法：在一个**全新对话**里，只给 Agent 本 Skill（不允许读历史项目、不允许读已有角色包），
> 让它从零生产第三个角色，跑完门径后统计"Skill 本身"暴露的缺口。
> 角色身份、画风均为示例 profile 下的虚构内容；本报告只收录可公开的流程与数据，不含私有角色名与内部路径。

## 1. 验证设计

- **隔离**：执行对话只能读 Skill 本体与一个空工作区；禁止参考任何已有角色资产。
- **纪律**：Skill 没覆盖的问题只记录、不允许现场改 Skill、不允许"自由发挥绕过"；逐门等用户过门。
- **范围**：核心门 G0–G9 全跑，用户追加扩展门 G10（微表情矩阵）、G11（机位与视线）、G12（场景包）；G13（风格变体）、G14（训练备料）本期有意裁剪。
- **生图口径**：单一闭源图像模型、每次请求单张；成品以保存到本地的 PNG 为准逐张目检。

## 4. 三条流程观察（判定为非缺口，记录口径）

1. **确认粒度**：Skill 本就规定"每门一次确认"；执行方一度逐张等确认，属于加戏。v1.1 起明确：门内执行方自检、崩图自行单格返工，整门干净版＋验收版一次交验。
2. **横版尺寸**：请求 2560×1440，模型实际返回 2730×1536（比例精确 16:9）；拼板按固定格 contain，无影响。记为模型侧口径，不改脚本。
3. **门控副本生命周期**：门范围中途扩展（G0–G9 → G0–G12）时自然产生第二份 profile 副本，印证 #002 的命名约定必要性。

## 5. 返工统计（生图侧，非 Skill 缺口）

- G4 细节 ×2：眼部微距被 Vision 剥皮（→ 促成 #005 的满幅微距路径）、领口出现胡茬级杂点（单格重出）。
- G7 道具单体 ×1：工具钳首版呈 V 形叉开废稿，重出合格。
- G10 微表情 ×1：一格 L2 取景与发型轻微漂移，单格重出。
- 配方 C（复杂人体几何先出几何参考图再二步生成）在端坐动作首验成功。
- 其余单元一次成图。

## 6. 验证结论

- **门径成立**：13 门在"只有 Skill、没有历史"的条件下可独立走通，封存 0 ERROR/0 WARN。
- **缺口集中在"模板完整性与工具兜底"，不在方法论**：8 条里 5 条是脚本健壮性/模板缺段、3 条是文档口径；提示词框架、门径顺序、验收清单本身零返工。
- **确定性脚本是质量底座**：全部 17 件拼板/商卡由脚本构建，无整板直出；唯一的阻塞缺口（#001）也正是"模板与脚本未对齐"，修复后同类问题被 exit code 封死。
- v1.1 修复后回归：/tmp 全新库 init→check 0 ERROR；缺段/互斥/空枚举/空族/色键五类路径均有自动化测试（见 `tests/`）。

## 7. 后续验证建议

- G13/G14 在需要训练备料的项目里补验。
